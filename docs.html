1. Current Architecture Overview

DukaanAI is an intelligent, voice-first Khata and store management system tailored for Indian Kirana and retail stores. It combines multilingual speech comprehension with real-time transactional double-entry accounting.

Backend Stack

  • FastAPI production server with multi-tenant data isolation
  • MySQL relational database engine with automated transaction rollbacks
  • Bodhan/Bandhon Cloud Indic STT API + Groq Indic LLM for high-speed intent parsing
  • Python qrcode generator endpoint (/api/payments/qr-code) with zero external network blocks

Frontend Stack

  • React 19 + TypeScript + Vite build pipeline
  • Tailwind CSS with glassmorphic dark UI and custom scrollbars
  • Dual login authentication: Mobile OTP (+91) & Email Address
  • Single hover-morphed sidebar navigation switch

2. Voice AI Query & Action Engine

The voice assistant supports seamless Kirana commands in Hindi, Hinglish, Odia, and English without requiring exact button clicks.

Transactional Actions

Analytical & Dataset Queries

list_customers "मेरी लिस्ट में कौन-कौन है?"

top_debtors "टॉप 3 / टॉप 5 सबसे ज्यादा उधार किसका है?"

cleared_debtors "किस-किस का खाता क्लियर हो चुका है?"

Partial Payment Guardrail: When a user mentions a specific payment amount while asking to update balance (e.g., "₹25,000 de chuka hai minus karke likh do"), the system strictly treats it as a partial payment (record_payment) and never wipes out the entire balance.

3. UPI Payment Collection Standards

DukaanAI follows the official NPCI (National Payments Corporation of India) standards for digital payment collections.

Why UPI PIN is NEVER stored or requested

In standard banking protocols, receiving money into a merchant account requires only the UPI ID (VPA) and the Merchant Display Name. A UPI PIN is strictly an authorization secret for sending/debiting money from an account. DukaanAI never prompts for or stores merchant UPI PINs.

Dynamic UPI URI Generation & Local QR Code Engine

QR codes and payment deep-links are generated dynamically using standard format:

upi://pay?pa=MERCHANT_UPI_ID&pn=SHOP_NAME&am=AMOUNT&cu=INR&tn=KHATA_PAYMENT

When scanned by Google Pay, PhonePe, or Paytm, the customer's app auto-fills the exact payable amount and merchant identity.

Local Python QR Engine (/api/payments/qr-code)

QR codes are generated directly by the backend using Python's qrcode and Pillow libraries. This eliminates external third-party dependencies, ensures zero CORS/adblocker failures, and renders instant PNG images offline in less than 3 milliseconds.

Automatic WhatsApp Delivery (Desktop & Mobile Universal Link)

Using the official https://api.whatsapp.com/send?phone=...&text=... universal link, DukaanAI automatically triggers WhatsApp without extra confirmations:

  • On Mobile Devices: Direct OS intent handoff to the native WhatsApp app with the customer's chat and pre-filled bill message.
  • On Desktop Computers: Opens WhatsApp Web or WhatsApp Desktop directly in the browser.
  • Message Payload: Includes personalized greeting, exact outstanding amount, direct 1-click UPI URI, and the locally rendered QR code link.

4. Unique Links & UTR Verification

To eliminate high gateway transaction fees (1.5% - 2%) and prevent payment fraud, the architecture supports direct verification:

Zero-Collision Tokens

Every payment request creates a unique 128-bit Nanoid/UUID token:

https://dukaanai.in/pay/pay_9f8a3b21c

Even with millions of concurrent customers, each token is mathematically collision-free and scoped strictly to that customer and shop.

Verification Flow

  • Customer receives WhatsApp / SMS link with pre-filled debt amount
  • Customer completes payment via any installed UPI app
  • Customer enters 12-digit UTR and uploads screenshot on the link
  • Merchant receives notification: "Review & Approve ₹2,000"

5. Future Cloud Migration (Vercel + bandhon.ai)

During local development, DukaanAI runs local CUDA models (SraVaani STT, Ollama, IndicF5). Moving to serverless cloud hosting (e.g. Vercel) requires migrating to external APIs.

Vercel Serverless Limitations

  • No GPU access on standard serverless instances
  • Strict execution time limits (10s to 60s per invocation)
  • Package bundle size limits (50MB - 250MB)

bandhon.ai Cloud Integration (STT & TTS Separation)

  • bandhon.ai STT: Offload Speech-to-Text to dedicated audio transcription endpoints (BANDHON_AI_STT_API_KEY & BANDHON_AI_STT_URL). Auto-falls back to Groq/local model if unavailable.
  • bandhon.ai TTS: Offload natural multilingual voice response generation to dedicated speech synthesis endpoints (BANDHON_AI_TTS_API_KEY & BANDHON_AI_TTS_URL).
  • Connect backend to remote cloud MySQL (PlanetScale / Supabase / RDS).

[FastAPI Backend ➔ MySQL Cloud DB]

6. Multi-Turn Voice & Same-Name Logic

Documented blueprint for future conversational advancements (kept lean for now to avoid premature complexity):

Missing Information Follow-Up (Clarification Loop)

If a shopkeeper gives partial information (e.g. "रमेश का उधार लिखो" without amount or items):

  • Step 1: System asks: "रमेश का कितना उधार लिखना है और क्या सामान लिया है?"
  • Step 2: If phone number is missing: "रमेश जी का फोन नंबर बता दीजिए ताकि रसीद भेज सकें?"
  • Step 3: Once answered, entry is finalized in the database.

Same-Name Ambiguity Resolution

If two customers have the same name (e.g., two "Ramesh"), the system avoids IDs and uses human-friendly anchors:

  • Phone Digits: "रमेश (...8043 वाले) या रमेश (...1234 वाले)?"
  • Outstanding Balance: "जिनका ₹2,100 बकाया है, या जिनका खाता क्लियर है?"
  • Disambiguation Tags: Prompting shopkeepers to add an identifier like "रमेश टेलर" or "रमेश स्टेशन रोड" upon creation.

7. Security, Privacy & Constraints

  • Frontend Cleanliness: Zero exposure of internal technical jargon (no mention of "MySQL", "Vercel", "IndicF5", or database engines on user-facing banners).
  • Multi-Tenant Isolation: Every database query is strictly filtered by shop_id to prevent cross-store leakage.
  • Repository Safety: Never commit secrets, API keys, or database credentials. Follow the strict "Dont PusBro" protocol (never push to Git remote).
  • Python Code Standards: Production Python files maintain zero inline comments (#).
